# 유스케이스 — 둘운완

마지막 갱신: 2026-10-03 · 정본 스펙 `PIVOT_DUOUNWAN_SPEC.md` §4~5

사용자 용어는 짝꿍·운동 약속·인증샷·인정·똑똑·내기·둘운완이다. 코드·데이터의 `partner`·`manager`·`plan`·`promise`는 같은 개념이며 그대로 유지한다. 구현 상태는 모두 `1.1.0+81` 코드 기준이고 **아직 배포 전**이다.

### UC-01. 짝꿍 초대하고 연결하기
- Goal: 내 운동 약속을 봐줄 연인·부부와 1:1로 연결한다.
- Actor: 초대자, 초대받는 사람
- Preconditions: 둘 다 짝꿍이 없다.
- Trigger: 첫 로그인 직후 초대 단계, 지금 탭 초대 카드, 우리 탭, 공유 링크 `nod-try.web.app/i/{CODE}`

Basic Flow:
1. 초대자가 `카톡으로 초대 보내기`를 누른다. 공유 시트에 "나 운동 약속 걸었어 🤙 … 코드 {CODE} → 링크" 메시지가 담긴다(약속이 없으면 "걸 거야").
2. 받는 쪽이 앱을 설치하고 로그인한다. 링크로 앱을 열었으면 코드를 보관하고 튜토리얼을 건너뛴다. 튜토리얼의 `초대 코드 받았어요`를 누르거나, 첫 로그인 뒤 1회 클립보드 확인에서 코드가 발견되면 바로 코드 확인으로 간다.
3. 코드 소유자를 조회해 `{초대자}의 운동 약속을 봐줄래요? [내가 봐줄게]` 확인 시트를 띄운다.
4. 연결되면 양방향 relation 2개가 생기고 `inviterId`·`inviteCode`가 함께 기록된다.
5. 서버(`onRelationCreated`)가 1:1을 검사하고, 두 사람의 초대 코드를 새로 발급하고, 기존 active 약속에 짝꿍을 지정하고, 초대자에게 `partner_connected` 푸시 1건을 보낸다.
6. 받는 쪽에 애칭 시트(UC-02), 이어서 `나도 걸래? [나도 걸기][나중에]`가 뜬다.

Alternate Flow:
- A. 이미 짝꿍이 있으면 입력 전에 막는다.
- B. 없는 코드·내 코드는 오류를 보여 준다(`not_found`, `self_code`).
- C. 다른 사람과 동시에 연결돼 1:1이 깨지면 서버가 새 관계를 지우고 `partner_connect_failed`를 보낸다. 화면은 입력 폼으로 돌아간다.
- D. 링크 랜딩(`/i/{CODE}`)은 지금은 코드를 클립보드에 복사하고 스토어로 보낸다. 설치 후 첫 로그인의 클립보드 확인이 그 코드를 잡는다. Play 링크에 `referrer=invite_code%3D{CODE}`를 붙이지만 앱은 아직 Install Referrer를 읽지 않는다. 설치된 앱을 바로 여는 Universal/App Link는 다음 릴리스.
- E. 나중에 초대: `나중에 초대할게요`로 넘어가면 지금 탭 초대 카드가 남는다. 공유 후에는 `짝꿍을 기다리는 중이에요` + `초대 다시 보내기`.

What the system must explain: 연결하면 운동 약속·인증샷·기록이 짝꿍 1명에게만 보이고, 언제든 끊을 수 있다.

### UC-02. 애칭 정하기
- Goal: 앱과 푸시에서 짝꿍을 내가 부르는 호칭으로 보이게 한다.
- Trigger: 연결 직후 홈 프롬프트(짝꿍당 1회), 우리 탭 짝꿍 카드의 `애칭 정하기/바꾸기`
- Basic Flow: 프리셋(짝꿍·자기·오빠·여보·애기) 또는 직접 입력(최대 10자) → 저장. `애칭 지우기`도 가능.
- Postconditions: `users/{me}.partnerNickname` 저장. 화면 라벨과 짝꿍에게서 오는 푸시 발신자 표시가 애칭으로 바뀐다.
- 상세: [policy/nickname_policy.md](./policy/nickname_policy.md)

### UC-03. 운동 약속 걸기
- Goal: 오늘부터 지킬 운동 약속을 한 화면에서 건다.
- Trigger: 지금 탭 빈 상태, `나도 걸기`, 우리 탭
- Basic Flow:
  1. `{애칭}한테 어떤 운동을 약속할까요?` 아래 운동 타일 14종 중 하나를 고른다(약속 한 줄·요일·마감 기본값이 채워진다).
  2. 요일(최소 1개), 마감 시각(필수)을 확인한다. 짝꿍의 최근 약속 요일이 미리 선택될 수 있다.
  3. `🤙 {애칭}이랑 손가락 걸기`를 누른다. 화면에 `못 하면 {애칭}한테 알려져요`가 보인다.
- Postconditions: `active` 28일 약속이 바로 생긴다(승인 대기 없음). 짝꿍에게 `🤙 {이름} 운동 약속 걸었어` 푸시.
- Alternate: 짝꿍이 없으면 `약속 시작하기`로 혼자 시작하고 `짝꿍 연결하기` 링크가 보인다. 빈 항목이 있으면 무엇이 비었는지 알려 주고 저장하지 않는다.

### UC-04. 오늘 운동 인증하기
- Goal: 오늘 운동을 사진 한 장(또는 없이)으로 기록한다.
- Preconditions: 오늘 예정된 active 약속이 있고 아직 기록이 없다.
- Trigger: 지금 탭 히어로 `오늘 🏃 러닝 했어?`(하루 종일), 마감 리마인더
- Basic Flow:
  1. `📸 인증샷 찍기` → (처음 1회) 동의 시트 → 카메라/앨범 → 미리보기 + 한마디(선택) → `인증하기`.
  2. 기기에서 1440px 축소·JPEG 재인코딩(EXIF·GPS 제거) 후 `proofs/{uid}/{planId}/{actionId}.jpg`에 올리고, 약속과 기록을 한 배치로 저장한다.
- Alternate:
  - A. `사진 없이 했어` → 메모 다이얼로그 → 기록.
  - B. `오늘은 쉴게` → 휴식권 사용(남아 있을 때).
  - C. 업로드 실패·8초 초과 → 사진 없이 기록하고 `사진은 못 올렸지만 오늘 기록은 남겼어요.`
  - D. HEIC 등 해독 불가 사진 → 토스트, 사진 없이 다시 시도.
- Postconditions: `completedDates`에 오늘, `actions` done 1건(사진 경로·출처·촬영 시각). 짝꿍에게 인증샷 푸시(짝꿍 빌드 81 이상일 때) 또는 일반 완료 푸시.

### UC-05. 짝꿍 인증 인정하기
- Goal: 짝꿍의 오운완을 한 번 탭으로 인정한다.
- Trigger: 인증 푸시, 지금 탭 짝꿍 카드, 기록 탭
- Basic Flow: 인증샷(출처 배지 `📸 방금 찍음 · 19:42` / `🖼️ 앨범 · 9/28 촬영`)과 메모를 본다 → ❤️🔥💪👏 중 하나를 탭한다.
- Alternate: `한마디`로 메시지와 함께 ❤️를 보낸다. 사진을 크게 보고 `신고하기`·`연결 끊기`를 할 수 있다.
- Postconditions: 오늘 done action에 `reaction`, plan에 `verifiedDates`. 실행자에게 인정 푸시 1건(중복 제거). 불인정 버튼은 없다.

### UC-06. 놓친 운동 — 짝꿍이 안다
- Goal: 마감이 지나도 기록이 없으면 혼자 묻히지 않게 한다.
- Actor: 시스템, 짝꿍, 실행자
- Preconditions: 짝꿍이 있는 active 약속, 오늘 예정, 마감 시각 있음, 오늘 done/skip/rest/rescue 없음
- Basic Flow:
  1. 마감 리마인더: `오늘 🏃 러닝 했어?` / `기록이 없으면 곧 {애칭}한테 알려져요`.
  2. 마감 + 30분 유예 뒤 크론(30분 주기)이 실행자의 시간대 기준으로 판정해 짝꿍에게 `action_missed` 푸시(하루 1회).
  3. 짝꿍 카드: `응원 보내기`(주) / `똑똑`(보조). 응원은 인정이 아니다.
  4. 똑똑은 약속당 하루 1회(서버 제한). 받은 쪽 카드에 `지금 간다 🏃` / `오늘은 봐줘 🙏` 원탭 답장.
- Postconditions: `lastMissedNotifiedAt` 기록. 답장은 `cheers`(`reactionType: 'reply'`) → 짝꿍에게 `poke_reply` 푸시.

### UC-07. 둘운완 이어가고 공유하기
- Goal: 둘 다 해낸 날을 쌓고 자랑한다.
- Basic Flow: 지금 탭 헤더와 우리 탭에 `둘이 함께 N일째`와 이번 주 나/짝꿍 도트. 오늘이 둘운완 데이가 되면 `오늘 둘운완이에요 🎉`, 하루 1회 공유 카드 시트(연속 3·7·30일엔 축하 문구).
- Postconditions: 9:16 PNG를 공유 시트로 보낸다(내 인증샷만, 짝꿍은 애칭 또는 `짝꿍`으로만). 첫 둘운완 데이·세 번째 인정 수신 뒤 평점 요청(최대 3회).
- 상세: [policy/duo_stats_policy.md](./policy/duo_stats_policy.md)

### UC-08. 내기 걸고 정산하기
- Goal: 비금전 내기로 동기를 더한다.
- Basic Flow: 짝꿍 카드 `내기 걸기` → `못 지키면`(기본 켜짐, 🍗 치킨 쏘기 등 칩) / `지키면`(선택, 🍣 같이 오마카세 등) → 일수 조건 → 제안 → 상대 수락 → active 칩 표시 → 28일 종료 시 정산 카드.
- Alternate: 돈 단어(만원, ₩, 현금, 송금, 계좌, 포인트, 숫자+원)가 있으면 저장을 막고 안내한다.

### UC-09. 인증샷 관리와 안전
- 내 인증샷 삭제: 사진 보기 메뉴 `사진 삭제`(본인만) → Storage와 기록의 사진 필드 삭제.
- 신고: `신고하기` → `devhohouse@gmail.com` 메일 초안(action ID 포함).
- 연결 끊기: 우리 탭 또는 사진 보기 → 확인 → 양쪽 약속의 짝꿍 해제, 진행 중 내기 rejected, 상대 기기 사진 캐시 삭제. 상대는 더 이상 내 사진을 읽을 수 없다(Storage 규칙이 현재 `managerId` 기준).
- 회원 탈퇴: 서버가 내 약속·기록·응원·인증샷·관계·사용자 문서를 지우고 타인 약속의 짝꿍 지정을 해제한다.

### UC-10. 기존 사용자 업데이트
- 업데이트 후 첫 홈 진입에 1회 공지: `그래,해봐가 둘운완이 됐어요` / `약속, 기록, 짝꿍 연결은 그대로예요.` 새 사용자에겐 안 뜬다.
- 이미 연결된 커플은 다음 홈 방문에 애칭 시트를 1회 본다.
- `config/app.minBuild` 미만이면 `업데이트가 필요해요` 전체 화면, `latestBuild` 미만이면 소프트 안내(빌드당 1회).
- 리마인더 문구는 업데이트 후 1회 전체 재예약된다(`notif.reminder_copy_version = 81`).

# 유스케이스

`실천 메이트`는 사용자에게 보여주는 용어다. 현재 코드와 데이터의 `partner`는 같은 1:1 관계를 뜻하며 호환성을 위해 유지한다.

### UC-01. 작은 실천 계획 만들기
- Goal: 혼자 미루기 쉬운 행동을 오늘 처리할 수 있는 작은 약속으로 만든다.
- Actor: 실천자
- Preconditions: 사용자가 로그인했고 새 플랜을 만들 수 있다.
- Trigger: 사용자가 플랜 추가를 선택한다.

Basic Flow:
1. 사용자가 공부, 운동, 직접 입력 중 카테고리를 고른다.
2. 추천 약속을 선택하거나 행동을 직접 입력한다.
3. 요일과 알림 시간을 정한다.
4. 실천 메이트에게 보일 설명을 확인하고 저장한다.
5. 연결된 메이트가 있으면 승인 대기, 없으면 활성 상태가 된다.

Alternate Flow:
- A. 추천 약속을 고르면 행동, 빈도, 알림이 자동 입력된다.
- B. 메이트가 없으면 혼자 시작할 수 있지만 확인과 똑똑을 받을 수 없다는 안내를 본다.
- C. 메이트가 조율을 요청하면 수정 후 다시 제안한다.

Postconditions:
- 28일 플랜과 예정 행동이 생성된다.
- 메이트 연결 여부에 따라 `pending` 또는 `active` 상태가 된다.

Implementation Status:
- 현재 구현

What the user must understand:
- 큰 목표보다 반복 가능한 작은 행동을 정하는 것이 우선이다.
- 메이트에게 행동, 일정, 설명이 공유된다.

What the system must explain:
- 메이트가 없으면 알림과 기록은 작동하지만 1:1 확인 루프는 작동하지 않는다.
- 저장 전 메이트에게 보이는 내용을 미리 확인할 수 있다.

Where to reduce choice fatigue:
- 카테고리별 추천 약속과 빈도를 먼저 보여준다.
- 고급 설정은 기본 흐름에서 숨긴다.

Defaults / recommendations to show:
- 기간 28일, 주 3일, 저녁 9시
- 학습 파일럿에서는 영어, 자격증, 코딩, 독서, 글쓰기 추천

### UC-02. 한 명의 실천 메이트와 연결하기
- Goal: 나의 작은 약속을 알아봐 주고 다시 이어줄 한 사람과 동의된 1:1 관계를 만든다.
- Actor: 초대하는 사용자, 초대받는 사용자
- Preconditions: 두 사용자 모두 로그인했고 다른 활성 메이트가 없다.
- Trigger: 사용자가 메이트 연결을 선택한다.

Basic Flow:
1. 초대하는 사용자가 연결 코드를 공유한다.
2. 초대받는 사용자가 코드를 입력한다.
3. 시스템이 코드와 중복 연결 여부를 확인한다.
4. 시스템이 양방향 관계를 생성한다.
5. 두 사람 모두 연결 완료 화면에서 서로 확인하고 응원하는 관계임을 본다.

Alternate Flow:
- A. 코드가 잘못됐거나 만료됐으면 다시 확인할 수 있는 오류를 보여준다.
- B. 이미 메이트가 있으면 현재 1명만 연결할 수 있다고 설명한다.
- C. 사용자는 연결하지 않고 혼자 시작할 수 있다.

Postconditions:
- 두 사용자에게 활성 1:1 관계가 생성된다.
- 서로의 제안, 실천, 놓친 약속을 동의된 범위에서 확인할 수 있다.

Implementation Status:
- 현재 구현

What the user must understand:
- 실천 메이트는 연인, 친구, 가족, 동료 등 관계 유형과 무관하게 직접 초대한 한 사람이다.
- 연결은 감시 권한을 주는 것이 아니라 서로의 약속을 확인하고 응원하는 동의다.

What the system must explain:
- 무엇이 공유되고 어떤 알림이 전달되는지 연결 전에 알려준다.
- 언제든 연결을 해제할 수 있고 해제 후 공유가 중단된다는 점을 알려준다.

Where to reduce choice fatigue:
- 메이트 유형을 고르게 하지 않고 코드 공유와 입력만 제공한다.
- 기본 CTA는 `한 사람 초대하기`로 둔다.

Defaults / recommendations to show:
- 가장 편하게 오늘의 실천을 물어봐 줄 한 사람을 추천한다.
- 사용자 용어는 `실천 메이트`로 통일한다.

### UC-03. 오늘 실천 완료하기
- Goal: 오늘의 작은 약속을 처리하고 실천 메이트가 알아볼 수 있게 한다.
- Actor: 실천자
- Preconditions: 오늘 예정된 활성 플랜이 있다.
- Trigger: 사용자가 지금 탭의 오늘 실천 카드를 연다.

Basic Flow:
1. 사용자가 `했어`를 선택한다.
2. 선택적으로 메모나 집중 기록을 남긴다.
3. 시스템이 완료 기록을 저장한다.
4. 연결된 메이트가 확인할 수 있는 상태와 알림을 만든다.

Alternate Flow:
- A. 오늘 실행하지 않기로 했다면 휴식권이나 건너뜀을 선택한다.
- B. 네트워크 오류가 나면 저장 실패를 알리고 다시 시도할 수 있게 한다.
- C. 메이트가 없어도 개인 완료 기록은 저장한다.

Postconditions:
- 오늘 행동이 완료, 휴식 또는 건너뜀 중 하나로 기록된다.
- 완료 기록은 메이트의 확인 대기 상태가 될 수 있다.

Implementation Status:
- 현재 구현

What the user must understand:
- 완벽한 결과보다 오늘 약속을 명확히 처리하는 것이 중요하다.
- 남긴 메모는 연결된 메이트에게 보일 수 있다.

What the system must explain:
- 각 처리 상태가 성공률과 정산에 어떻게 반영되는지 알려준다.

Where to reduce choice fatigue:
- 기본 행동은 `했어`로 두고 휴식권과 건너뜀은 보조 행동으로 둔다.

Defaults / recommendations to show:
- 메모는 선택 사항
- 시작이 어렵다면 5분 집중 타이머 추천

### UC-04. 실천 메이트의 완료를 확인하고 응원하기
- Goal: 상대의 실천이 혼자 묻히지 않게 알아보고 다음 행동으로 이어지는 피드백을 보낸다.
- Actor: 실천 메이트
- Preconditions: 상대가 완료한 미확인 기록이 있다.
- Trigger: 완료 알림을 열거나 지금 탭·히스토리에서 상대 기록을 본다.

Basic Flow:
1. 메이트가 완료 기록을 확인한다.
2. `확인하고 응원 보내기`를 선택한다.
3. 리액션 또는 짧은 코멘트를 보낸다.
4. 시스템이 기록을 확인됨으로 표시하고 상대에게 전달한다.

Alternate Flow:
- A. 코멘트 없이 빠른 리액션만 보낸다.
- B. 상대가 오늘 예정된 약속을 모두 완료하면 요약 카드에서 한 번에 확인한다.
- C. 지금 답하기 어렵다면 건너뛰고 나중에 기록을 연다.

Postconditions:
- 확인 시각과 피드백이 기록된다.
- 실천자는 자신의 행동을 한 사람이 알아봤다는 신호를 받는다.

Implementation Status:
- 현재 구현

What the user must understand:
- 확인은 평가나 감시가 아니라 상대의 실천을 알아봤다는 짧은 신호다.

What the system must explain:
- 보낸 리액션과 코멘트가 상대에게 어떻게 보이는지 알려준다.

Where to reduce choice fatigue:
- 추천 리액션을 먼저 보여주고 코멘트는 선택 사항으로 둔다.

Defaults / recommendations to show:
- 기본 CTA: `확인하고 응원 보내기`
- 빠른 응원 리액션 8종

### UC-05. 미뤄진 약속에 똑똑 보내기
- Goal: 상대의 미처리 약속을 비난하지 않고 다시 시작할 계기로 만든다.
- Actor: 실천 메이트
- Preconditions: 상대에게 오늘 예정된 미처리 약속이 있고 똑똑 조건을 충족한다.
- Trigger: 메이트가 지금 탭의 미처리 카드를 본다.

Basic Flow:
1. 메이트가 `똑똑! 하기`를 선택한다.
2. 시스템이 짧은 확인 신호를 상대에게 보낸다.
3. 상대가 알림을 열고 오늘 약속을 처리한다.

Alternate Flow:
- A. 메이트가 아무 행동 없이 카드를 닫는다.
- B. 상대가 이미 처리했다면 중복 똑똑을 보내지 않는다.
- C. 반복 미실천이면 조율이나 약속 변경을 제안한다.

Postconditions:
- 똑똑 전송이 기록되고 상대에게 한 번 전달된다.
- 상대는 완료, 휴식, 건너뜀 또는 조율로 복귀할 수 있다.

Implementation Status:
- 현재 구현

What the user must understand:
- 똑똑은 비난이나 독촉이 아니라 서로 합의한 확인 신호다.

What the system must explain:
- 같은 약속에 보낼 수 있는 빈도와 노출 조건을 알려준다.

Where to reduce choice fatigue:
- 기본 똑똑은 한 번 탭으로 보내고 추가 메시지는 선택 사항으로 둔다.

Defaults / recommendations to show:
- 기본 문구: `오늘 약속, 어떻게 됐는지 기다리고 있어요.`
- 중복 전송 방지

### UC-06. 보상·벌칙 약속 정산하기
- Goal: 4주 결과를 두 사람이 함께 확인하고 다음 플랜 여부를 정한다.
- Actor: 실천자, 실천 메이트
- Preconditions: 플랜 기간이 끝났고 약속 조건 또는 완료 기록이 있다.
- Trigger: 시스템이 플랜을 완료 상태로 전환한다.

Basic Flow:
1. 시스템이 완료 일수와 약속 조건을 계산한다.
2. 양측에게 결과 카드를 보여준다.
3. 각 사용자가 결과를 확인한다.
4. 실천자는 다음 4주 플랜을 만들거나 종료 사유를 남긴다.

Alternate Flow:
- A. 보상·벌칙 약속이 없으면 실천 기록만 정산한다.
- B. 목표에 닿지 못해도 조정된 다음 플랜을 제안한다.
- C. 한쪽이 아직 결과를 확인하지 않아도 기록은 보존한다.

Postconditions:
- 결과 확인 상태가 저장된다.
- 다음 플랜 또는 종료 사유로 연결된다.

Implementation Status:
- 현재 구현

What the user must understand:
- 정산은 사람을 평가하는 것이 아니라 약속 결과를 함께 확인하는 단계다.

What the system must explain:
- 완료, 휴식, 인정, 건너뜀 상태가 결과에 어떻게 반영됐는지 보여준다.

Where to reduce choice fatigue:
- 결과 확인 후 `다음 4주 이어가기`와 `여기서 마치기`를 우선 노출한다.

Defaults / recommendations to show:
- 기존 행동과 빈도를 유지한 다음 플랜을 기본 제안한다.

### UC-07. 놓친 약속 자동 전달
- Goal: 약속 시간이 지났는데도 처리하지 않은 행동이 혼자 묻히지 않게 한다.
- Actor: 시스템, 실천 메이트, 실천자
- Preconditions:
  - 실천자와 메이트가 연결되어 있다.
  - 플랜이 `active` 상태다.
  - 오늘 요일에 해당하는 항목과 알림 시간이 있다.
  - 오늘 `done`, `skipped`, `rested`, `rescued` 처리가 없다.
- Trigger: 예정 시간과 유예시간이 지난 뒤 서버 스케줄러가 실행된다.

Basic Flow:
1. 시스템이 오늘 처리되지 않은 활성 플랜을 찾는다.
2. 같은 날짜에 미실천 알림을 이미 보냈는지 확인한다.
3. 메이트에게 약속이 아직 처리되지 않았다는 푸시를 보낸다.
4. 메이트가 똑똑, 실천 인정 또는 조율을 선택한다.
5. 실천자가 완료, 휴식권, 건너뜀 또는 사유 전달로 약속을 처리한다.

Alternate Flow:
- A. 실천자가 뒤늦게 완료하면 메이트에게 완료 보고를 별도로 전달한다.
- B. 휴식권을 쓰면 추가 미실천 알림을 보내지 않는다.
- C. 메이트에게 FCM 토큰이 없으면 푸시는 생략하고 다음 앱 진입 시 상태 카드로 보여준다.

Postconditions:
- `plans.lastMissedNotifiedAt`이 오늘 날짜로 기록된다.
- `action_missed` 푸시는 같은 플랜에 하루 최대 1회 전달된다.
- 사용자가 직접 처리하기 전까지 오늘 행동은 미처리 상태로 남는다.

Implementation Status:
- 부분 구현

What the user must understand:
- 연결과 알림 시간을 동의한 경우 놓친 약속이 메이트에게 전달될 수 있다.
- 미처리는 사라지지 않지만 완료, 휴식, 건너뜀 또는 조율로 정리할 수 있다.

What the system must explain:
- 자동 전달은 처벌이나 감시가 아니라 한 사람의 확인으로 복귀를 돕는 신호다.
- 알림을 끄거나 연결을 해제하면 전달 범위가 달라진다.

Where to reduce choice fatigue:
- 실천자에게 `했어`, `휴식권`, `건너뜀`을 우선 노출한다.
- 메이트에게 `똑똑`, `실천 인정`, `조율 요청`을 우선 노출한다.

Defaults / recommendations to show:
- 기본 유예시간 30분
- 기본 문구: `약속 시간이 지났어요. 오늘 어떻게 됐는지 한 번 물어봐 주세요.`
- 같은 플랜의 미실천 푸시는 하루 1회
